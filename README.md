# ERP 流程練習室（erp-workflow-practice）

「企業資源規劃」課程的**非官方**練習工具，與任何 ERP 軟體廠商無關。
介面依課堂操作畫面重新製作（圖示、配色都是自己畫的），讓沒辦法進電腦教室的時候也能練完整流程。

> 資料只存在你自己電腦的瀏覽器裡，不會上傳到任何地方。請不要輸入真實密碼或個資。

## 使用方式

1. 打開網頁，用 `admin` / `admin` 登入（公司別：學生區）。
2. 左邊的程式樹或右邊流程圖上**亮起來的方塊**可以開啟作業。
3. 「工具」頁籤可以 **匯出資料**（備份成 JSON）、**匯入資料**、**重置資料**（回到空白）。
   換電腦或清除瀏覽器資料前，記得先匯出。

## 考試流程（依序練習）

| # | 作業 | 重點 |
|---|---|---|
| 1 | 登入者代號建立作業 ADMI10 | 建立使用者 |
| 2 | 使用者權限建立作業 ADMI05 | 給使用者可以執行的程式和功能 |
| 3 | 品號資料建立作業 INVI02、客戶資料建立作業 COPI01 | 基本資料 |
| 4 | 報價單建立作業 COPI05 | 新增 → 存檔 → 確認 |
| 5 | 客戶訂單建立作業 COPI06 | 複製前置單別（報價單）→ 存檔 → 確認 |
| 6 | 訂單變更單建立作業 COPI07 | 選訂單 → 改數量、填變更原因 → 確認後版次 +1 |
| 7 | 訂單轉請購單複製作業 COPB10 | 批次作業，到「佇列工作控制台」看結果 |
| 8 | 請購單建立作業 PURI05 | 查詢 → 確認請購單 |
| 9 | 請購單維護作業 PURI06 | 修改供應廠商、採購人員等採購資訊 |
| 10 | 請購資料更新作業 PURB01 | 請購轉採購（批次作業） |
| 11 | 採購單建立作業 PURI07 | 確認採購單 |
| 12 | 進貨單建立作業 PURI09 | 複製前置單別（採購單）、填驗收數量 → 確認後入庫 |
| 13 | 銷貨單建立作業 COPI08 | 複製來源（訂單）→ 確認（庫存不足會擋下） |

另外有「庫存狀況查詢」可以看目前庫存。

## 和課堂系統可能不同的地方（推測部分）

截圖沒拍到的畫面和行為是依常理推測的，之後有截圖再修正：

- 採購單建立作業（PURI07）的畫面版面
- 訂單、進貨單、銷貨單等其他子頁籤的內容（練習版顯示「未使用此頁籤」）
- 確認、存檔時的訊息文字，以及錯誤訊息
- 單據確認後的畫面變化（確認者欄位、按鈕狀態）
- 工具列每個按鈕的確切名稱
- 登入畫面
- 「庫存狀況查詢」的程式代號（所以標題不顯示代號）
- 倉庫名稱、品號單價與成本
- COPB10「依前置天數推算」需求日：請購日期 + 品號固定前置天數
- PURB01 產生的採購單是**未確認**，要到 PURI07 確認
- 轉請購不扣除現有庫存，依訂單未交數量全額請購
- 報價單單身「預計出貨日、生效日、失效日」的欄位順序（截圖只拍到規格欄，順序參考同學的專案）；選品號後生效日先帶單據日期；轉成訂單時，預計出貨日會帶到訂單的預交日
- 付款條件的選項清單（月結30天、月結60天、貨到付現）
- 左邊程式樹裡截圖沒展開的資料夾內容（練習版留空）
- 佇列工作控制台除了「批次」以外的頁籤（練習版一律空白）
- 使用者權限的群組、他組、附件權限只記錄不檢查；「轉出檔案」「設計權限」不可設定
- 批次作業的「區間選擇」、「自訂」、「週期性」只有外觀

其他限制：

- 訂單變更單確認後不能取消確認
- 預設只有 `admin` 一個使用者，其他使用者請在 ADMI10 自己建立（這本來就是考試的第一步）
- 不提供列印、週期性排程

## 資料來源

以下預設資料取自同學的專案 [tailing-cloud/workflow-erp-conductor](https://github.com/tailing-cloud/workflow-erp-conductor)（MIT 授權）：

- 廠商 27 筆
- 客戶 1001、1002、1003、1004、1109
- 品號 410004、800001、800002、900001、900002、900003、900006（原資料沒有主供應商；庫別 W01 對應到 P001 原料倉）
- 稅別碼：銷售用 S01～S22、採購用 P01～P22（依發票聯式分組）。訂單管理系統預設 S02，採購管理系統預設 P02

代號相同但內容不同的（客戶 1107、品號 900004、410001），保留依課堂截圖建立的資料，因為考試流程會用到。
已經在用的瀏覽器資料，重新整理後會自動補上缺少的廠商、客戶、品號，已有的資料不會被改動；稅別碼則整份換成新的清單。

## 開發

```bash
npm install
npm run dev     # 本機開發
npm test        # 跑完整流程測試
npm run build   # 型別檢查 + 打包
```

React + Vite + TypeScript，資料用 zod 檢查，存在 localStorage。
推到 `main` 會由 GitHub Actions 自動部署到 GitHub Pages。
